Two different things often get called "Bedrock gateway," so here's both — the RAG piece first, since that's the actual work.

**Part 1 — Build the RAG (Bedrock Knowledge Bases)**

1. **Enable model access** — Bedrock console → Model access → request an embedding model (Titan Text Embeddings v2 or Cohere Embed) and a generation model (Claude, etc.). Region matters; pick one where both are available.
2. **Stage your docs in S3** — PDF, TXT, HTML, CSV, DOCX, MD are supported. One bucket/prefix per data source.
3. **Pick a vector store** — S3 Vectors (cheapest, newer), OpenSearch Serverless, or Aurora PostgreSQL + pgvector. If you don't bring your own, Bedrock will create an OpenSearch Serverless store for you, but that carries a minimum OCU cost.
4. **Create an IAM service role** — needs `bedrock:InvokeModel` on the embedding model, `s3:GetObject`/`ListBucket` on your bucket, and write access to the vector store.
5. **Create the Knowledge Base** — Bedrock console → Knowledge Bases → Create. Attach the S3 data source, choose chunking (fixed ~300 tokens, semantic, or hierarchical), select the embedding model.
6. **Sync** — run the ingestion job. Re-run whenever S3 content changes (or trigger via Lambda on S3 events).
7. **Query** — `Retrieve` for chunks only, `RetrieveAndGenerate` for a full grounded answer with citations. Add metadata `.metadata.json` sidecar files if you need filtered retrieval.

**Part 2 — The gateway layer**

- **Bedrock Access Gateway** (aws-samples repo) if you want an OpenAI-compatible `/v1/chat/completions` endpoint so existing OpenAI SDK code works unchanged. You store an API key in Secrets Manager, then deploy a CloudFormation stack — the newer version supports API Gateway + Lambda for true response streaming instead of ALB, taking about 10–15 minutes.
- **API Gateway + Lambda** if you're wrapping your own `RetrieveAndGenerate` call — gives you auth, throttling, and WAF in front of the KB.
